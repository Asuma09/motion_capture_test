# Hand-Motion Glass Break

MacBook の内蔵カメラに向かってパンチすると、画面上のガラスパネルが割れる macOS ネイティブゲーム。コントローラも画面タッチも使わず、手の動きだけで操作する。

**Swift / AVFoundation / Vision / SpriteKit / macOS**

---

## 作った目的

Apple の Vision フレームワークによる手の姿勢推定を、「実際に遊べるもの」として成立させられるか試した個人プロジェクト。カメラ映像から手の位置を取るだけなら難しくないが、**意図した動作だけを拾う**ところが本題になる。

## 技術的な核心 — パンチを「速さ」ではなく「手のひらの拡大率」で検出する

最初の実装では、手の 2D 座標の移動速度が閾値を超えたらパンチとみなしていた。しかしこの方式は、**横方向に手を振っただけでパンチと誤検知する**。カメラから見れば「速く動いた」という点で区別がつかないためだ。

そこで判定基準そのものを変えた。手首から中指付け根（middle MCP）までの距離を「手のひらサイズ」の代用値とし、**その増加率**でパンチを判定する。

```
手がカメラに近づく → 手のひらが画面上で大きくなる  ← パンチ
手を横に振る       → 手のひらのサイズは変わらない  ← 無視される
```

奥行き情報を持たない通常のカメラでも、見かけのサイズ変化から前方向の動きだけを取り出せる。実装では次の点に気をつけている。

- **固定時間窓での微分を取る。** 直前フレームとの差分はノイズが大きいため、`(時刻, 手のひらサイズ)` のリングバッファを持ち、**約120ms 前**のサンプルを基準に増加率を計算する。過去0.5秒より古いサンプルは破棄する
- **クールダウンを置く。** 1回のパンチで複数フレームが閾値を超えるため、検出後 0.35 秒は次の判定を行わない
- **信頼度でフィルタする。** 手首と middle MCP の `confidence` がともに 0.3 を超えたフレームだけを使い、手が外れたら履歴をリセットする
- 閾値は正規化された手のひらサイズ単位で 0.45 / 秒

この変更は `Detect punches via palm-size growth, not 2D speed` としてコミット履歴に残している。

## その他の実装上の判断

- **カメラ処理とゲーム処理をスレッドで分離した。** `AVCaptureSession` と Vision の推論は専用の `DispatchQueue` で回し、結果だけをデリゲート経由でメインキューに渡す。描画をブロックしない
- **落ちたフレームは捨てる。** `alwaysDiscardsLateVideoFrames = true` を設定し、推論に失敗したフレームは例外を投げずに無視する。手の追跡はフレーム単位でベストエフォートでよい
- **鏡像にする。** Vision は左下原点の正規化座標を返すため、X を反転して「鏡に映った自分」と同じ方向にカーソルが動くようにした
- **カメラ権限の3状態を扱う。** 許可済み／未確認／拒否で分岐し、拒否時はシステム設定への案内文を画面に出す
- **推論は端末内で完結する。** 映像を外部に送信しない。App Sandbox を有効にしたまま、カメラの entitlement だけを与えている

## ゲーム側の作り

- ガラスパネルは最大6枚。HP は3で、1回のパンチごとに**ヒビが放射状に増えていく**（SKShapeNode で中心から乱数方向に線を引く）
- HP が0になると24個の破片に飛散して消え、スコアが入る
- 重なったパネルは手前のものを優先してヒットさせる

## 動かし方

```bash
open motion_capture_test.xcodeproj
```

Xcode でビルドして実行し、カメラの利用を許可する。前面カメラに手をかざすとシアンのインジケータが追従し、画面のガラスに向かってパンチすると割れる。

必要環境: macOS（Xcode でビルド可能なバージョン）、内蔵または外付けカメラ。

## 制約

- 同時に追跡する手は1つ（`maximumHandCount = 1`）
- 閾値はハードコードしており、照明条件やカメラからの距離によっては調整が必要
- 検証は単一の Mac 環境のみ
